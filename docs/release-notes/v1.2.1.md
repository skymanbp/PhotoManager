## 1.2.0 → 1.2.1

**先看这两条**

- **安全（横切审计 #81，critical）**：「整理新照片」页的「AI 建议地点」与「分类推送」页的 AI 分类，此前让 `claude -p` 以照片目录（或主库）为工作目录。`-p` 模式不做工作区信任确认，目录里预埋的 `.claude/settings.json`（hooks）、`.mcp.json`、CLAUDE.md 会被直接加载——一张动过手脚的存储卡，点一下「AI 建议地点」就能以你的身份执行任意命令（真实 claude 2.1.280 复现）。现在 claude 在 pm 自己的空目录（系统临时目录下 `pm-claude-cwd`）里运行，照片目录只经 `--add-dir` 放行读取，另加 `--safe-mode`、`--setting-sources user`、`--strict-mcp-config`；两层各自单独都挡得住（逐层实测）。
- **转换的颜色（#82）**：`pm convert` 此前把 CMYK / LAB 源（tif、psd…）朴素转成 RGB，还把源的 CMYK 配置原样嵌进 jpg，颜色是错的。现在带 ICC 的非 RGB 源按色彩管理转成 sRGB、嵌 sRGB；配置与输出颜色空间对不上就报错、不出图。**以前转过 CMYK / LAB 源的**：已派生的件不会自动重转，用 `pm convert --redo <路径…>` 重新派生。

**行为变化**

- **退出码按 DESIGN §5.1 统一**：命令行用法错误、`pm backup` 找不到备份盘（未登记 / 未挂载 / 多卷身份冲突）、逃出命令体的 IO 异常，现在都退 **2**（此前是 1，与「有差异 / 有待办」同码）。脚本里若把 1 当失败，请复核。
- **`pm doctor --deep` 把核对无误的验证时间记回索引**（锁内、只写 `.pm/`；锁被占、root 不可写时明说没记上），`pm status` 的「最久未验证字节」深验后随之刷新。`scripts/verify_backup_entries.py --verified-on` 按日期筛出的集合随之变化：回读过的不再落在写入那天。
- **云端占位与 Dedup / WOF 文件**：此前被当成链接整批跳过（放在 OneDrive 上的库扫不进去），现在照常枚举；**云端未下载**的文件不读（读就会触发整库下载），在 `pm scan` / `pm sort` 与「整理新照片」页里单列「云端未下载」。
- **暂存区与布局层名不分大小写**：手建的 `to-be-sync'd`、`raw` 就是暂存区（NTFS 本就不分）；按目录开了大小写敏感、两种拼写并存时拒绝并说明，不替你挑。
- `config.toml`、`.gitignore` 开头的 UTF-8 BOM 照 git 的做法跳过（此前 BOM 让每条 pm 命令起不来 / 让 `.pm/` 那行不算数）。
- **输入的值域有了唯一定义**：四个 `--workers` 与配置里的并发数统一 1..64，越界在解析处拒绝（手编越界值在 `pm scan` 时拒绝、`pm config` 标 ⚠）；`pm sort --from/--to` 只收四位年份的 `YYYY-MM-DD`；空路径参数（`--main ""`、`pm backup init ""`、`pm sort ""`）拒绝，不再当成当前目录。
- **打包版 pm-ui 起不来时**（还没有配置、端口绑不上、窗口建不起来）弹系统消息框说明原因、以 2 退出，不再一声不响就没了。
- 终端里 stdout 被重定向时，屏幕上的扫描进度不再按 936 乱码。

**恢复与诊断更可信——「查不出」不再说成「没有」**

- doctor、`pm names`、vault 比对、sort 概览、计划删除等处的「存在不存在 / 是不是目录」改三态：ACL 拒绝、介质错误不再被说成「不存在」「无痕迹」，而是如实报「查不出」、不据此做任何修复。
- 计划页的失效草稿判定：源查不出按「源还在」，`pm plan prune` 不会因此删计划。
- `pm trash empty` 清除后补写收尾标记，下一次 doctor 不再把刚清掉的隔离载荷误报成 C4。
- 手编计划不能再把 trash 根或 manifest 当改名源搬进用户数据（#43）。
- undo 隔离（从 trash 改回原位）后索引补回那一条；扫描时读不出（被占 / 介质读错）的文件，旧条目按「查不出」保留，不从快照里消失；`doctor --repair` 不删还有未完成计划引用的派生件。
- 备份盘：登记路径上 `root-id.json` 损坏或读不出时点名报出（不再说「未挂载，插上盘」）；手编成绝对路径的 subpath 说清原因；读索引途中掉线按掉线等盘；`scripts/verify_backup_*.py` 途中盘没回来时照写已核出的结果、退出码 3。
- GUI：执行中途中断答「执行中断（可能已有项落位）」而不是「没有执行」；内核整批拒绝答 409「没有执行」；索引 / 候选读不出带原因显示；设置页数字项留空点保存不再静默写 0（掉线等待写 0 会关掉瞬断保护）；AI 建议在途时重扫，晚到的建议整批丢弃，不再填进别的分段。
- vault：非 jpg 的 DRIFT 只报告、不进推送计划；`pm vault push` 直推后刷新缓存；photos.json 未配置时照片记录报 `unknown`（此前报 `pending`，`/photo-publish` 会据此重复上线）。
