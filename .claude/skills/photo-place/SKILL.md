# photo-place —— 给 `pm sort` 的分段补上「地点」这一格

`pm sort` 能从 EXIF 读出**拍摄时间**，读不出**地点**——本机相机实测零 GPS。
设计因此把地点留成命令行参数：「GUI 与将来的 AI 都只是替用户填这一格，走同一条
计划路径」（`docs/DESIGN-COMMANDS.md` §7）。这个 skill 就是那个"填格子的"。

**它不碰任何文件，也不调用任何写端点。** 产物只有一段可复制的命令。

## 边界（照抄不变量，不要放宽）

- **只出建议**。地点由用户确认；模型看错了地方是常态（同一栋楼、连锁店招牌、
  雪山长得都像），而 `pm sort` 用这个名字**决定照片被移到哪**。
- **不进 pm 内核**。pm 里没有任何 AI 判断；这一格填完之后走的是与手工输入
  **逐字相同**的那条计划路径。
- **不改 `--from/--to`**。分段边界是时间证据，`pm sort` 已经给出；模型没有
  比时间戳更好的依据（真实库里纽约与亚特兰大首尾相接，看图也分不开）。
- 建议不出来就说不出来。**不猜**（I1）。宁可让用户自己敲一个地点。

## 步骤

### 1. 拿到分段

```
pm sort "<源目录>"
```

它打印每段的时间范围、张数、首尾文件名，以及每段该敲的命令模板。
把这些**原样**留着——下一步只往模板里填地点。

### 2. 每段抽样看图

每段取 3–5 张，优先取**首、中、尾**（一段里换过地方时，只看首张会以偏概全）。
文件名从上一步的「首 / 尾」拿；中间的用 `ls`/`Get-ChildItem` 按名字序取。

用 Read 工具直接读那几张图。RAW（`.ARW`/`.DNG` 等）读不了，此时：

- 若同目录有同 stem 的 JPG（相机双格式），读那个；
- 否则**跳过这一段**，明确说"这一段没有可看的图，地点请你给"。

不要为了看图去转码——那要引外部依赖，而这个 skill 的全部价值就是零副作用。

### 3. 给建议，并说出依据与把握

每段一行，格式：

```
段 N（<起> → <止>，<张数> 张）：建议 <地点>　依据：<看到了什么>　把握：高/中/低
```

- **依据**要具体到画面里的东西（路牌、建筑、植被、车牌、语言文字），不要写
  "看起来像"。说不出具体依据 = 把握低。
- 把握**低**的段，建议里写 `<地点?>` 并明说"这一段我判不准"。

### 4. 拼命令

用 `pm sort` 第 1 步给出的模板，只替换地点：

```
pm sort "<源目录>" --place <地点> --from <起> --to <止>
```

已有同年月事件夹时（第 1 步会打印 `↺ 已有同年月事件 <名>`），改用：

```
pm sort "<源目录>" --event <完整事件名> --from <起> --to <止>
```

两者的区别只在**要不要自动拼年月前缀**：`--place Atlanta` 会生成
`26-08-Atlanta`，而 `--event 26-08-Atlanta` 直接用给定的名字（并入已有事件时用
它，免得拼出第二个同月目录）。

### 5. 交给用户

把命令列出来，明确说这是**建议**、需要他确认地点之后自己执行。
不要代跑——`pm sort` 会生成计划文件，那是写盘。

## 反例（不要这样做）

- ❌ 直接执行 `pm sort … --place …`：地点没经用户确认就落进计划。
- ❌ 因为"看着像"就给一个高把握：这一格错了，照片进错事件夹，事后要靠
  `pm undo` 回滚。
- ❌ 调整 `--from/--to` 去"合并两段"：时间证据是 pm 给的，改它等于用一个更弱的
  依据覆盖一个更强的。要合并请让用户直接给跨段的日期区间。
- ❌ 给 RAW 转码/装解码库：这个 skill 的边界就是零副作用、零新依赖。

## 与 GUI 的关系（P8-D）

pm GUI「整理新照片」页的「AI 建议地点」按钮走**同一契约**：`pm serve` 的
`POST /api/suggest {kind:"place"}` 自己重跑分段、每段首/中/尾均匀抽至多 5 张 jpg
交给用户自己账号的 `claude -p --permission-mode plan` 看图，答案只**预填**空着的地点格，
把握低的填成 `<地点?>`，每段一行依据；只有 RAW 的段答「没有可看的图」。
不自动生成计划——地点仍由用户确认后点「生成计划」（DESIGN-P8.md §22）。
