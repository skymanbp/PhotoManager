      计划

      凡是动照片字节的写盘都是两段式：先生成计划，再执行；执行后可 pm undo 回滚。执行可以在这里点「执行这个计划」（要点两次确认），也可以在终端 pm apply <id>——两条路走的是同一套装载/复验/日志。（「暂不同步」是例外：它不碰照片，只在主库 .pm 里记一条决定，直接写、随时可撤。）

      设置 路径与并发；改完立刻生效，不用重启

      主库（只读）
      主库是所有身份的锚点（root 标识、日志、索引都挂在它下面）。改它等于换一个库，一台机器设一次——在终端 pm init --main <路径>。
      vault 展示集目录
      photos.json（可选；配置了下面的 portfolio 仓路径则必填）
      两个用途：RENAME 的只读引用检查（被它引用的文件名不会被改名，会打断已上线的图片链接）；以及上线命令里 portfolio 仓唯一会 add 的文件——它必须在 portfolio 仓内。
      并发数
      扫描的并行度，1..64。备份盘不读它——那边默认单线程防 HDD 寻道抖动，要改用终端 pm backup --workers N。
      上线命令（「状态」页的复制入口用）
      「复制上线命令」按 vault 目录 + 这三项生成两仓的 git 提交/推送命令：展示集仓只显式 add landscape / portrait / urban 三个类目，portfolio 仓只 add 上面的 photos.json（所以填了 portfolio 仓路径就必须同时设 photos.json，否则拒绝生成——永不整仓 add）。路径只接受盘符绝对路径且只含字母数字、空格与 -_.()'+,=@~#&，push 目标形如 origin main。pm 从不替你执行 git（不变量 I9）——复制后自己粘进终端，看清再回车。
      备份硬盘
      登记会在那块盘上建立备份 root 标识（已经是备份 root 就沿用），并按 UUID + 盘内相对路径记住它——以后换盘符也认得出。照片不动。

      四步上手

      1. 看状态：左侧「状态」一眼看清三件事——Raw / 成片 / 相册各多少、相册与 vault 差哪些、备份盘上次什么时候同步。
      2. 整理与归档：「整理新照片」把相机卡按拍摄时间分段进暂存区；「归档」把暂存区事件夹归入 Raw/成片（可同时导入相册）、把成片 jpg 挑进相册、把 tif/png 派生成 jpg。每一步都只生成计划。
      3. 分类推送：「分类推送」里给每张 NEW 照片选 landscape / portrait / urban（可先点「AI 建议分类/地点」预填），点「保存决定并生成推送计划」。这一步只写计划文件与主库 .pm 里的记录，不碰照片。
      4. 执行：到「计划」页点「执行这个计划」（点两次确认），或在终端跑 pm apply <id>——同一套校验写入 + 日志，随时 pm undo。之后按提示做 git 提交，或用「状态」页的「复制上线命令」（pm 从不替你执行 git）。

      安全模型：GUI 是独立进程，从不直接触碰照片文件；一切经 pm serve 的本机 API。pm 没有删除与覆盖原语——唯一的移出机制是带清单的隔离区。AI 只出建议：跑在你自己账号的 claude -p 只读模式下，构造上写不了任何东西。
