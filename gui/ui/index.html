        计划 先生成，再执行；执行后可撤销

        说明

        凡是动照片的写盘都是两段式：先生成计划，再在这里点「执行这个计划」（要点两次确认），或在终端 pm apply <id>——同一套校验与日志，事后 pm undo 回滚。执行态从日志折叠而来（计划文件本身不回写）；「已失效」= 从未执行、而每条待办的源都已不在盘上的草稿。「删除」与「清理已执行/失效」只删可再生成的计划文件，日志与 undo 不受影响。

        主库（只读）
        换主库 = 换一个库，一台机器设一次：终端 pm init --main <路径>。
        展示集（vault）目录
        备份硬盘
        在那块盘上建备份标识（已有就沿用），按 UUID 认盘，换盘符也认得。照片不动。
        高级设置
        photos.json（可选；填了下面的 portfolio 仓路径就必填）
        改名计划会只读查它：被它引用的文件名不改（会打断线上图片链接）；也是上线命令里 portfolio 仓唯一会 add 的文件——必须在 portfolio 仓内。
        并发数
        只影响扫描（1..64）。备份盘默认单线程防 HDD 寻道抖动，要改用终端 pm backup --workers N。
        上线命令（「状态」页「复制上线命令」用）
        按 vault 目录 + 这三项生成两仓的 git 提交/推送命令：展示集仓只显式 add landscape / portrait / urban 三个类目，portfolio 仓只 add 上面的 photos.json（所以填了 portfolio 仓路径就必须同时设 photos.json，否则拒绝生成——永不整仓 add）。路径只接受盘符绝对路径且只含字母数字、空格与 -_.()'+,=@~#&，push 目标形如 origin main。pm 从不替你执行 git——复制后粘进命令行，看清再回车。
        备份盘掉线等待
        备份 / 检查途中 USB 盘瞬断时，最多等它回来多少秒，然后从中断处接着跑（已落好的文件不重做）。0 = 关闭，出错就停。

        四步上手

        1. 看状态（按 1）：「现在该做什么」列出待办，点它就跳到对应页。索引旧了点「扫描」（= 终端 pm scan，几秒；首次全量 10–25 分钟）。
        2. 整理 → 归档（按 2、3）：「整理新照片」把相机卡按拍摄时间分段进暂存区；「归档」页点「扫描并归档」，暂存区事件夹归入 Raw / 成片（可同时进相册）。每一步都只生成计划。
        3. 分类推送（按 4）：给每张新照片选类目（可先「AI 建议分类/地点」预填），点「保存决定并生成推送计划」。
        4. 执行（按 5）：在「计划」页点「执行这个计划」，点两次确认；事后可 pm undo。要上线：回「状态」页点「复制上线命令」，再点「打开命令行」，粘贴、看清、回车——pm 从不替你执行 git。
        安全模型

        GUI 是独立进程，从不直接触碰照片文件；一切经 pm serve 的本机 API。pm 没有删除与覆盖原语——唯一的移出机制是带清单的隔离区。AI 只出建议：跑在你自己账号的 claude -p 只读模式下，构造上写不了任何东西。「打开命令行」只是开一个窗口（pm 已在 PATH），里面敲什么由你定。
