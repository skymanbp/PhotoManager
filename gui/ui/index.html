    计划

    凡是动照片字节的写盘都是两段式：先生成计划，再 pm apply <id> 执行；执行后可 pm undo 回滚。这里只看，不执行。（「暂不同步」是例外：它不碰照片，只在主库 .pm 里记一条决定，直接写、随时可撤。）

    主库（只读）
    主库是所有身份的锚点（root 标识、日志、索引都挂在它下面）。改它等于换一个库，一台机器设一次——在终端 pm init --main <路径>。
    vault 展示集目录
    photos.json（可选）
    只用于 RENAME 的只读引用检查：被它引用的文件名不会被改名（会打断已上线的图片链接）。
    并发数
    扫描与备份的并行度，1..64。
    备份硬盘
    登记会在那块盘上建立备份 root 标识（已经是备份 root 就沿用），并按 UUID + 盘内相对路径记住它——以后换盘符也认得出。照片不动。

    三步上手

    1. 看状态：左侧「状态」一眼看清三件事——Raw / 成片 / 相册各多少、相册与 vault 差哪些、备份盘上次什么时候同步。
    2. 分类推送：「分类推送」里给每张 NEW 照片选 landscape / portrait / urban，点「生成推送计划」。这一步只写计划文件，不碰照片。
    3. 执行：在终端跑页面给出的 pm apply <id>；执行是校验写入 + 日志，随时 pm undo。之后按提示做 git 提交（pm 从不替你执行 git）。

    安全模型：GUI 是独立进程，从不直接触碰照片文件；一切经 pm serve 的本机 API。pm 没有删除与覆盖原语——唯一的移出机制是带清单的隔离区。
